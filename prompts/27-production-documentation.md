# 27. Production documentation

```text
Create production-quality documentation for this orchestrator.

Docs to create/update:
- README.md
- docs/ARCHITECTURE.md
- docs/API.md
- docs/AGENT.md
- docs/SCHEDULER.md
- docs/RECONCILER.md
- docs/ROLLOUTS.md
- docs/HEALTHCHECKS.md
- docs/SECURITY.md
- docs/OBSERVABILITY.md
- docs/RELIABILITY.md
- docs/OPERATIONS.md

Documentation should explain:
- what problem this orchestrator solves
- what it intentionally does not solve yet
- architecture
- component responsibilities
- service/task/node lifecycle
- deployment flow
- scaling flow
- rolling update flow
- failure recovery
- local development
- production deployment assumptions
- security model
- operational runbooks

Keep docs accurate to the current code.
Do not document features that are not implemented unless clearly marked as roadmap.
```
